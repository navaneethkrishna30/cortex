# Rules

1. Memory is the summary; follow links only when the task needs more. Max 2 hops.
2. One fact, one place. Never copy a fact into another note; link to it.
3. The thing that moves owns the relation. Use only the relation types in core/relations.md.
4. When a fact changes, use update or supersede. Never create a second note on the same subject.
5. Read a note before editing it, and pass its hash back with the edit.
6. If memory and an older doc disagree, memory wins; the doc is history.
7. Search docs/ and logs/ only when the user asks. If search reports matches there, tell the user.
8. Never delete; to forget, move the note to .archive/.
9. Write debriefs only when the user runs /debrief.
